# Riskium: an ontology for enterprise risk knowledge

A register entry, a possible scenario, an assessment result and supporting evidence can concern the same risk without being the same thing. Riskium separates these subjects and records the context needed to interpret their relationships. The conceptual model owns their definitions; the guide explains how to read and use them.

## Start with the question you need to answer

For meaning and scope, read the [overview](../overview.md), [scope](Scope.md) and [modeling decisions](../modeling-decisions.md). The [use guide](Using-the-Model.md) connects those distinctions to inspection and implementation tasks.

For scientific assessment, follow the [requirements](../../requirements/ontology-requirements.md) and [competency questions](../../requirements/cq/README.md) into [evaluation](Evaluation.md). The recorded results have different populations and limits; they do not combine into an overall correctness score.

For implementation, begin with [database assurance](../relational-assurance.md), then the [reproduction instructions](../reproducibility.md). For lookup and visual inspection, use the [visualization guide](Visualization.md).

## Which version am I reading?

The latest published source distribution is **[v0.3.2](https://github.com/ArazSaieArasi3/riskium/releases/tag/v0.3.2)**. The ontology model remains **0.3.1**; the distribution includes independently versioned engineering and documentation components. The conceptual and OWL reference downloads preserve the original model source. [Publication and versions](Publication.md) explains current pages, frozen snapshots and source releases.

The published scope received owner review with assistant support. Independent semantic review has no recorded responses, and the software is a bounded research implementation. Read [evaluation](Evaluation.md) and [limitations](../portal-limitations.md) when deciding what the artifact supports.
