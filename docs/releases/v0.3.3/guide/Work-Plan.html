Riskium/Work and release plan

Current work and release plan

The latest source distribution, v0.3.2, is published and its downloaded source inventory is verified. The ontology remains 0.3.1. The publication record identifies exact sources and checks; the artifact register separates model, requirements, manuscript, implementation and documentation versions.

Current documentation work

WIDOCO, the conceptual reference, the text explorer and WebVOWL are deployed. The completed Pages upgrade, #38, brought those views into one reading experience and corrected stale explanations. Its implementation and browser review are recorded separately from the released scientific evidence. Frozen documentation and source assets remain historical records.

The formal reference delivery, #33, is documented in the maintained formal-method guide, which connects the languages, assumptions, all 25 clause dispositions, original obligation/case IDs, later bounded alternatives and reproduction routes. The issue records exact publication verification and closure evidence; this explanation adds no scientific execution. The bounded relational child #40 adds assessment-correction overlay 0.3.0: immutable lineage, migration 4, historical query/RDF checks and 36 matching synthetic scenarios. Source/scenario and general assertion correction remain #35/#12. The current consistency guide records audit #39 across requirements, all native elements, manuscript claims and correction requirements. The next release task is #41: freeze a deliberate component set and publish the next stable public source distribution before broader mapping work continues.

Cross-document consistency checkpoint

#39 is a mandatory review before the next stable source freeze. The selected SQL child #40 and formal-reference task #33 are complete. Audit #39 is recorded in the central traceability guide; #41 must recheck its affected rows and live-channel evidence at the final selected source. If a documentation-only stable release comes first, audit that candidate without waiting for SQL. Bind the review to one commit and all artifact versions/digests; recheck affected rows after any change and verify the deployed channels after publication.

Extend the existing requirement/CQ, constraint, manuscript and SQL ledgers into one source-to-claim table. Each row must connect the source/requirement ID, model element, implementation or exclusion, fixture/oracle, observed receipt, retained claim and limit, manuscript/guide/Wiki/Pages location, exact version/hash and unresolved issue. Review terminology, denominators, examples, source citations, commands, links and historical/current status across README, ORSD/DRSD, sources, article, Wiki, Pages and release assets. Resolve critical contradictions before tagging; record bounded exclusions explicitly. Preserve frozen snapshots.

This gate checks documentation consistency and trace completeness; it does not wait for every research issue or imply scientific correctness. The full acceptance checklist is in #39.

Independent judgment Actual independent initial ratings and adjudication #23
Deployment acceptance Actual PostgreSQL/private migration, workloads, recovery/roles and user acceptance #36

Each packet needs a declared task, exact inputs, expected positive and negative outcomes, executed evidence and explicit limits. A small reviewed release can advance one bounded packet without waiting for every wider research objective.

Evidence boundaries

The original HermiT 281/295 scoped PASS and 14 NOT_RUN remain unchanged. The historical SHACL ledger remains 341 scoped PASS, one PARTIAL and 17 NOT_RUN out of 359. Later alternatives do not relabel those engine-specific rows. Independent-review responses remain zero, and all eleven organizational identity candidates remain WITHHELD.

A better reference interface, a passing CI build or a verified release download does not establish overall ontology correctness, independent scientific acceptance or production readiness. Evaluation explains the support each evidence population provides.
