# First release checklist

A migration snapshot is not automatically a stable scientific release. The first release must state its intended maturity and claims.

- Fix the exact model, documentation and evaluation versions.
- Resolve native model and formalization scope, including unsupported constraints.
- Complete the approved formal-coverage profile and publish its actual results and limits.
- Reconcile requirements, competency questions, diagrams and definitions.
- Review evidence, independent validation and standards claims at their declared scope.
- Select a license and finish citation metadata; create no placeholder DOI.
- Reproduce the build and required checks in a clean environment.
- Verify the exact public file inventory and source-bound generated outputs.
- Publish and read back the Wiki and Pages content when available.
- Bind any manuscript to the exact evaluated release rather than a moving branch.
- Publish release notes, checksums, remaining limitations and correction/deprecation rules.

Choose a development or prerelease designation when stronger scientific or implementation claims remain unsupported. Missing optional infrastructure must not be disguised as implemented capability.
