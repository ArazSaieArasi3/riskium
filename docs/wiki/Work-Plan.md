## Complete remaining scope

Publication work includes the missing WebVOWL graph viewer, stable/current documentation architecture, shared Wiki/Pages explanations, CI-gated deployment, formal-method discoverability, search/diagram routes and fresh deployed/interface acceptance. Actual WIDOCO 1.4.25, conceptual reference, hypertext OWL explorer, diagram assets, four RDF serializations, citation/rights notices and prior publication evidence already exist. Maintenance must preserve them.

Database work includes remaining source/scenario/threshold/indicator and responsibility mappings; general assertion/assessment correction lineage; multiple assertions and selection policies; time/interval/workflow/authority rules; and justified computed formulas/conversions. They remain #12/#5/#35 until a scoped policy and actual evidence exist. PostgreSQL, the authorized private 128-table migration and real deployment/user acceptance are separately routed to #36. A source-accounted element, JSON payload or populated table is not automatically complete task support.

Source/semantic work includes the original fourteen HermiT NOT_RUN and seventeen SHACL NOT_RUN routes, global C-08 PARTIAL, complete retained profile/task admission, qualified normative appetite/tolerance/owner interpretation, detailed prior-art access/reading, broader independent cases and actual independent meaning review. Later scoped engineering alternatives do not rewrite those historical populations. Original ORSD priorities and all twelve requirement/eight CQ dispositions remain visible.

Optional domains, external alignments and additional language/solver platforms are conditional enhancements, not silently required for the next release. The completed [17-record extension ownership/adoption policy](https://github.com/ArazSaieArasi3/riskium/blob/main/docs/extensions-and-bridges.md) covers the three boundaries, seven bridges, local anchor, three domain proposals and three alignment candidates. Adoption requires a specifically scoped new issue/version, source/license/identity decisions, CQs and real evidence; closing #16 did not implement them. A DOI/archive deposit, published-article status, exhaustive standards compliance or predictive/production validation is not claimed by the present artifacts. Such a claim needs its own requested scope and evidence.

## Traceability and change management

Keep the chain **source/locator → original requirement/CQ/clause → derived DRSD requirement → mapping/SQL/OWL/profile → frozen input and independent expected answer → actual result → component version/hash → release**. The [database assurance guide](Database-Assurance), [mapping trace](https://github.com/ArazSaieArasi3/riskium/blob/main/evaluation/relational/assessment/traceability.md), [artifact compatibility table](Artifact-Versions) and issue acceptance criteria identify the owners at each step. Explanations are projections, not new semantic authorities.

For each small packet, name retained claims and exclusions first, update only affected requirements/documents, fix the oracles before implementation, run affected checks, record defects, and bind a clean exact source. Changed model, policy, source/cohort, query, schema or fixture invalidates its affected evidence and requires a fresh replay/review. Unchanged components keep their own versions; a distribution version need not equal every model/document/database version. The new release mechanism must enforce this explicitly rather than weakening the current v0.3.1-only guard.

No need to finish every row before another stable release. Once order 1's bounded maintenance scope and order 2's exact publication gates pass, that packet can become the next stable release. WebVOWL, larger mappings and scientific review can follow as separate small releases with honest scope. Every newly discovered retained-scope critical defect must be fixed before its packet is published.
