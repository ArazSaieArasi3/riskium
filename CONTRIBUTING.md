# Contributing

Explain the domain problem, the proposed change and its supporting evidence. Identify affected concepts, relations, constraints, requirements and tests. State both the intended result and a case the change must reject or leave unentailed.

Keep public text in English. Use descriptive titles and concrete explanations. Internal task identifiers belong in supporting metadata rather than primary reader navigation.

Change a definition in the model before updating its summaries. Regenerate derived references rather than maintaining a second definition. Preserve stable semantic identifiers unless an explicit identity-change decision is recorded.

Include only material intended and authorized for public distribution. Do not copy private records, restricted source documents, full development archives or unreviewed dependencies. File selection and content review happen before a public push, including pushes to a draft branch.

Run the documented checks. Report their actual scope; never describe a structural check as independent semantic validation or a planned reasoner test as executed.
