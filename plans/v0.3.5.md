## Result sought

A reader can retrieve an original evidence-reference version, all explicitly declared correction branches and the exact application context's selected/withdrawn state at an explicit ledger boundary. Original sources and item/target pins survive unchanged. A reviewer can then trace each retained current claim through one source-bound artifact/evidence/manuscript register rather than joining incompatible dated summaries by hand.

The paper and the engineering distribution have separate identities. A checked distribution can be released while the paper remains NOT_READY. Conversely, a paper restricted to an already supported scientific baseline need not wait for unrelated deployment work or every future SQL feature.

## Why this successor

| Alternative | Assessment |
| --- | --- |
| Complete every native rule, 236 deferred mappings, production port and independent case study in one release | The original criteria are not yet scoped or evidenced for that population. It combines unrelated dependencies and cannot provide a credible finite exit. |
| Ship only another SQL extension | It advances #35/#12 but leaves the current cross-artifact and manuscript alignment question unresolved. |
| Refresh status prose alone | It improves reading routes but does not deliver the next declared lifecycle behavior. |
| **Bounded lifecycle plus current traceability, v0.3.5** | It advances the actual remaining source/correction task, preserves the scientific baseline, makes current claims auditable and defines finite release and submission exits. This is the recommended next package. |

The choice is judged against value to the existing research questions, explicit evidence gaps, finite testability, compatibility, reviewer effort and preservation. It is a reasoned current recommendation, not a proof that no future information could improve the scope. Any newly discovered critical semantic issue must change the affected claim/design before publication.

## Deliverable A: bounded lifecycle behavior

The [0.7.0 contract](../implementation/relational/0.7.0/contract.json) declares nine derived requirements. The [fixed prospective controls](../implementation/relational/0.7.0/fixtures.json) retain their unchanged declaration-time null/NOT_RUN fields. [Current actual execution](../evaluation/relational/evidence-lifecycle/report.json) separately records all 43 fixed controls PASS, four inherited native oracles, three wrong-query controls and one separately counted weakened-rule experiment.

Scope is **already represented issued C065 EvidenceReference versions**. It does not add a general native Assertion class or claim complete arbitrary assertion lifecycle semantics.

- Add only explicit same-artifact correction declarations, retaining one immutable parent per child, all branches and source attribution. Plain issuance creates no correction edge.
- Record append-only, documentary SELECT/WITHDRAW/CLEAR decisions scoped to an exact artifact and a caller's supplementary policy context.
- Require an explicit as-of ledger sequence. A newer issue, different context, equal label or later correction does not select a branch automatically.
- Return NO_SELECTION when no selection exists; SELECTED for the explicitly selected non-withdrawn version; WITHDRAWN with no selected pointer when that version is withdrawn in that context. Preserve the earlier pointer in historical events, without fallback.
- Keep actor/source/locator/reason/interpretation and recorded order distinct from artifact origin, endpoint sources and any real-world authority/validity.
- Preserve existing named native graphs and contextual C066 roles. No new authority/occurrence/correction predicate or historical union is introduced.
- Execute actual populated v7→v8 migration, old-row/schema/hash/native preservation, nested rollback, repeat/failure controls, backup/reopen/dump and deliberate wrong-query/weakened-rule controls.

Reinstatement and correction of a withdrawal notice, R-69..R-72, other unsupported assertion families, complete authority/mandate/workflow/formula semantics, PostgreSQL/private migration and operational acceptance retain their broader issues. They cannot be counted as lifecycle passes.

Each applicable route must bind:

**source identity/edition/locator → original requirement/CQ → native element/clause → representation or explicit omission → implementation/query → fixed fixture/oracle → actual observed receipt/runtime → retained claim and limit → exact manuscript paragraph/table or NOT_CLAIMED_IN_PAPER → current documentation and frozen release.**

Bidirectional checks must detect orphan retained claims, missing source IDs, stale hashes, denominator confusion, wrong-version evidence, lost negative cases and undocumented native/supplementary differences. Every one of the 306 source IDs needs a current disposition; deferred/partial/external entries stay visible. An explicit justified exclusion completes accounting, not implementation or adequacy.

Cover conceptual JSON/native exchange/OWL projection, SQL schema/dictionary/queries/migrations, ORSD/DRSD/CQs, source registers, figures/tables, manuscript, owner/independent records, current guides/Wiki/Pages, component matrices and release assets. Bounded exports need declared omissions rather than an unsupported full-equivalence claim.

Private historical binaries must be identified as historical/unavailable or separately verified; do not report them as current public reruns. ## Conference readiness is a separate decision

Use the [conference-readiness contract](../docs/conference-readiness.md) and [machine-readable gate state](../evaluation/releases/v0.3.5-definition/readiness.json). The selected venue/track/deadline is currently unspecified. No calendar submission date is supportable from the repository alone.

A defensible submission candidate needs a bounded contribution, legitimate related-work/source comparison (#37), actual evidence for every retained case/evaluation claim (#13/#4/#5), independent critical semantic scrutiny under the project's protocol (#23), an exact final manuscript and reproducible evidence bundle, and the chosen venue/coauthor gates. These project gates do not assert a universal requirement that all conferences demand a particular reviewer protocol or badge.

Deployment/private migration and all 236 deferred mappings need not finish if the paper excludes those claims. Completion of every broad issue is not the submission criterion. Retained unsupported central claims, unreconciled figures/denominators, or venue/coauthor requirements are blockers.
