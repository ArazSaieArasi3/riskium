# Using Riskium and application profiles

Begin with the [current source catalog](https://github.com/ArazSaieArasi3/riskium/blob/ce0baefa3495d1bc3b42f56ad578154d5bc4f178/ontology/0.3.2/riskium-model.json), identify the relevant objectives and context, and assign traceable case identifiers. Preserve the distinction among the case, records about it, possible scenarios, actual occurrences and assessment results.

Choose and declare the task being performed. The analytical task checks explicitly supplied analytical context; the local operational-register task additionally applies its declared approval and registration conditions. Unknown approval remains unknown. A record for another case cannot authorize the target case. A source IRI establishes traceability, not independent authorization.

Customize through explicit application profiles or compatible extensions. Record added requirements and provenance, retain the core meanings, and test the intended exchange. Do not silently convert local governance rules into universal ontological existence conditions.
